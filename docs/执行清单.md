## Phase 2 🧪 算法实现与正确性验证

### 2.1 史莱姆区块判定函数（CPU 先行验证）

- [ ] **P1** 实现 `isSlimeChunk(seed, chunkX, chunkZ)` 判定逻辑：
      ```
      输入：worldSeed（64位），区块坐标 (chunkX, chunkZ)
      
      第一步：构建Random种子（⚠️ 所有int运算是32位溢出截断，不能用64位！）
        int t1   = chunkX * chunkX * 0x4c1906;         // 32位int溢出截断
        int t2   = chunkX * 0x5ac0db;                   // 32位int溢出截断
        int t3_z = chunkZ * chunkZ;                      // 32位int溢出截断
        long t3  = (long)t3_z * 0x4307a7L;              // 截断后转long再乘
        int t4   = chunkZ * 0x5f24f;                     // 32位int溢出截断
        long seedForRandom = (seed + t1 + t2 + t3 + t4) ^ 0x3ad8025fL;

      第二步：Java Random.setSeed()
        seedForRandom = (seedForRandom ^ 0x5DEECE66D) & 0xFFFFFFFFFFFF;

      第三步：Java Random.next(31)
        seedForRandom = (seedForRandom * 0x5DEECE66D + 0xB) & 0xFFFFFFFFFFFF;
        int bits = (int)(seedForRandom >>> 17);

      输出：bits % 10 == 0 → 是史莱姆区块
      ```
- [ ] **P2** 确定目标 MC 版本，确认该版本的判定算法是否有差异（1.12 ~ 1.21+ 基本一致，但仍需以目标版本源码为准）
- [ ] **P1** 用已知史莱姆区块坐标验证函数正确性

### 2.2 滑动窗口 + 行前缀和算法

- [ ] **P1** 实现单种子的完整验证流程：
      ```
      输入：worldSeed
      网格：(-200,-200) 到 (200,200)，共 401×401 个区块

      逐行扫描（z 从 -200 到 200）：
        1. 对当前行 z，计算每个 x 的 isSlimeChunk(seed, x, z)
           同时构建该行的前缀和数组 prefix[0..401]
           prefix[0]=0, prefix[i+1]=prefix[i] + slime[x][z]（0或1）

        2. 将当前行的前缀和存入循环缓冲区
           循环缓冲区容量 = 5 行，通过 (z % 5) 索引覆盖旧行

        3. 当已扫描行数 ≥ 5 时（z >= -196），
           对每个 x 窗口起点（-200 ≤ x ≤ 196）：
             对 5 行分别取 prefix[x+5] - prefix[x]（O(1) 求行内窗口和）
             累加 5 行的结果得到 5×5 窗口总和
             若总和 ≥ 19 → 记录种子，立即终止
      ```
- [ ] **P1** 确认每种子复杂度：401行 × 401列判定 + 401次前缀和构建 + 396×5次窗口查询 ≈ **320k 次操作/种子**
- [ ] **P1** 确认每种子内存占用：5行 × 402个 int = **~8KB/线程**

### 2.3 CPU 验证

- [ ] **P1** 在 CPU 上实现上述算法（单线程即可），用 1 万 ~ 100 万种子测试正确性
- [ ] **P2** 记录 CPU 单线程性能基线（种子/秒），供后续 GPU 版对比

## Phase 3 💻 CUDA 内核实现

### 3.1 设备函数

- [ ] **P1** 将 `isSlimeChunk` 移植为 CUDA `__device__` 函数
      - 注意 64 位整数运算在 GPU 上的正确性（使用 `long long`）
      - 确保与 CPU 版输出完全一致

### 3.2 搜索内核

- [ ] **P1** 实现 CUDA 内核 `search_kernel`：
      ```
      线程布局：每个线程处理一个种子，线程间互不依赖
      
      每个线程的工作：
        1. 根据 threadIdx + blockIdx × blockDim 计算本线程的起始种子
        2. 以 gridDim × blockDim 为步长遍历种子序列
        3. 对每个种子执行 2.2 节的滑动窗口验证流程
        4. 找到符合条件的种子时：
           a. 通过原子操作（atomicAdd）获取结果槽位
           b. 写入种子值到全局结果数组
           c. 置全局 found 标志，所有线程检查后提前退出
      ```

### 3.3 主机端调度

- [ ] **P1** 实现主机端主循环：
      - 划分种子范围（用户指定 start ~ end）
      - 分批启动内核（每批覆盖一定数量种子，避免 GPU 超时）
      - 每批启动后检查结果标志，有结果则终止
      - 无结果则继续下一批

- [ ] **P2** 实现断点续传机制：
      - 每完成一批种子，将当前进度写入磁盘文件
      - 启动时检查断点文件，从中断位置继续

- [ ] **P2** 实现结果输出：符合条件的种子写入文本文件，一行为一个十进制种子值
